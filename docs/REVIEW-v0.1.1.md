## 审查修复和设计选择

1. **资金准确性**：金额以分保存；禁止零、负数、超过两位小数与越界金额。多个显式金额要求拆分。退款/转账/还款未实现，阻止误计收支。
2. **日期准确性**：日期严格校验，固定北京时间，不依赖手机时区。过去的提醒与循环提醒拒绝保存；月日/星期等复杂表达保留待补充，不猜成今天。
3. **误执行与重复点击**：任何识别都先进入核对界面。未知意图需手动选择；异步写入有互斥锁。一次输入一条记录。
4. **数据保护**：加载成功前不允许添加；损坏数据不覆盖；写入失败不清空草稿。首次启动没有演示流水。
5. **通知一致性**：先持久化记录，再安排通知；稳定记录 ID 作为通知标识。失败状态有重试入口；完成/删除取消通知。若通知状态写入失败，尝试取消已安排通知。
6. **能力真实性**：AI 页面标明本地规则和未连接服务。未把设置后端地址等同于接入成功，未向外部业务服务发送记录。
7. **密钥保护**：无真实 `.env`、令牌、密钥、签名文件或用户历史数据。客户端不接收提供商密钥；`.env.example` 只有空配置与安全说明。

## 依赖审计

`npm audit --omit=dev` 返回 9 个 moderate、0 个 high、0 个 critical 条目。它们来自同一条 Expo 构建工具依赖链：`expo → @expo/config-plugins → xcode → uuid@7.0.3`，关联 `GHSA-w5hq-g745-h8pq`（v3/v5/v6 的缓冲区边界检查）。

检查已安装 `xcode/lib/pbxProject.js`，其 UUID 调用为 `uuid.v4()`，本应用记录 ID 使用 `expo-crypto.randomUUID()`。当前没有发现业务输入到公告所述方法的路径；这不是无漏洞保证。npm 建议的自动修复会将 Expo 降到 46，破坏本版 SDK，故未执行强制降级或不兼容覆盖。后续升级 Expo 时复查这条依赖。

## 待真机验收与后续边界

- 小屏幕、键盘遮挡、动态字体和通知权限流程需要真机验收。
- 操作系统通知与本地存储不能形成跨系统原子事务；在取消/写入同时失败或进程被强杀的极端情况下，用户需要在工作台重试。v0.1.1 未实现启动时与系统通知队列自动对账。
- AsyncStorage 没有本应用级别的加密或云备份；记录多时当前 ScrollView 列表不做虚拟化。
- 导出、历史编辑、循环待办、云同步与真正的大模型接口留给后续版本。

## iPhone 验收步骤

1. 启动后切换四页，检查底部导航和 + 入口。
2. 录入一条测试记账，核对账户金额，确认前检查数据未增加，确认后查看统计。
3. 关闭并重新打开应用，确认记录仍在；创建待办并完成/恢复。
4. 创建未来几分钟的提醒，分别测试允许/拒绝通知；锁屏等待，完成后确认未到期通知取消。
5. 保存每日复盘，筛选查看；检查大字体和打开键盘时保存按钮可滚动到达。
